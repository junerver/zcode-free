ZCode 福利自动领取助手 · 使用说明
================================================

一、这是什么
------------------------------------------------
到点自动打开签到目标客户端 → 截图 → 领取 → 校验结果。支持多个应用:
  · 视觉流程:截图交给 DeepSeek 视觉模型,自己找「领取」按钮再点(适合 ZCode)。
  · 固定坐标流程:在面板里把要点的位置录下来,按顺序点(适合按钮位置固定的应用)。
  · 领取后补关:领完之后按录制好的位置再点一下,把「领取成功」浮窗关掉。
    浮窗留着不关,下一场开场第一下就点在浮窗自己身上,既领不到也认不出界面。
失败会自动关客户端重开重试(默认 5 次)。面板(浏览器里的那个页面)用来
配置目标、录制坐标、安排场次、查看日志与截图回放。

每个应用还能各自设定领取周期:不限周期(每场都跑)/ 每天一次 / 每周一次。
选「每天一次」或「每周一次」时,本周期已经领到的目标会被静默跳过,不白开客户端。

程序只在本机运行,截图与 API Key 都不会上传到任何第三方服务。


二、怎么启动
------------------------------------------------
双击 ZCodeAssistant.exe 即可,会自动用默认浏览器打开面板。

关闭浏览器不影响后台自动领取;要结束程序:
  · 面板里「设置 → 退出程序」,或
  · 在任务栏通知区域找到它并结束任务

注意:同一时间只能运行一个实例。重复双击会提示"已经在运行中",
这是有意设计——两个实例会把同一场次领取两次。


三、首次配置(面板里 6 步)
------------------------------------------------
1. 签到目标页:确认 ZCode 的程序路径(点「探测路径」),领取周期选「不限周期」
   就是每天每场都跑;要加别的应用就点「添加目标」。
2. 固定坐标的应用:在该目标行点「固定坐标」,再点右上「截图」(应用没开就先点
   「启动并截图」),然后在图上按顺序点击要按的位置,每点一次记一步。
   录完点「校验坐标」确认这些点还落在窗口内,再用「演练」走一遍不点击的流程。
3. 领取后补关:先手动领一次,让「领取成功」的浮窗显示出来,再在录制面板上方
   切到「录到领取后补关」,点「截图」,在图上点浮窗的关闭按钮(一下即可)。
   这一步只有视觉流程的应用(ZCode)必须录;固定坐标的应用如果领完会弹窗
   (如 Trae 的券弹窗),同样建议录上。程序只在**领取成功之后**才补这一下,
   补关没点动也只留一条提醒,不会把已经到手的福利判成失败。
4. 识别页:走视觉流程的目标需要 DeepSeek API Key(platform.deepseek.com 创建,
   需小额余额),填好点「连接与额度测试」。只用固定坐标的目标可以跳过这步。
5. 场次表页:添加每天的时间场次(如 10:00 / 16:00),「目标」留「全部目标」
   就按签到目标页的顺序挨个跑;也可以为某个应用单独排一场。
6. 顶栏「总开关」打开。

建议先点「概览 → 演练一次」跑一遍(会置顶窗口并截图识别,但不点击、
不关客户端),确认界面能正常抓到后再点「试领一次(完整流程)」。


四、数据存在哪
------------------------------------------------
exe 同级的 data 文件夹:

  data\config.yaml    设置与 API Key(明文,请勿分享这个文件)
  data\logs\          运行日志,按天切分,默认保留 7 天
  data\shots\         每次尝试的截图留档,默认保留 7 天

如果 exe 放在 Program Files 这类没有写权限的位置,数据会自动改存到:
  %LOCALAPPDATA%\ZCode福利助手\data

整个文件夹一起复制就能搬到别的机器(onedir 打包,不能只拿 exe)。


五、系统设置建议
------------------------------------------------
程序会阻止系统与显示器休眠(否则到点了进程醒着、调度却不会触发),
但它阻止不了锁屏——锁屏是安全策略,不是电源策略。建议:

  · 屏幕保护程序:无
  · 锁屏超时:从不

一旦锁屏,该场次会被判为「需人工」并跳过,不会浪费重试次数。
如需"睡眠也能唤醒领取",要用 Windows 任务计划程序(勾选"唤醒计算机
运行此任务"),属另一套方案。


六、杀毒软件提示
------------------------------------------------
本程序没有代码签名,且会模拟鼠标点击,可能触发:

  · 首次运行弹「Windows 已保护你的电脑」→ 点「更多信息 → 仍要运行」
  · 杀软报可疑 → 把 ZCodeAssistant.exe 加入信任/白名单

请只从可信来源获取本程序。


七、常见问题
------------------------------------------------
问:总开关开着但不触发?
答:检查场次是否勾选启用、系统时间是否正确;日志页有每次触发记录。
   也确认电脑没有锁屏——锁屏时会跳过本场。

问:识别不准 / 点不到按钮?
答:视觉流程用识别页「测试识别」看红框位置;确认执行时窗口在前台、未被遮挡;
   必要时把福利页停到固定界面再调提示词与置信度阈值。
   固定坐标流程则在「签到目标」页重新截图、重录,或用「校验坐标」看哪一步
   已落到窗口外(标红);每一步点完之后的画面都存在 data\shots,回放能看出
   是哪一步没跳出预期界面。

问:试运行「鼠标压根没动、一下都没点」?
答:多半是权限不匹配。客户端若「以管理员身份运行」,Windows 会把它挡住,
   低权限程序发出的鼠标操作被静默丢弃(截图能看见、日志却像点了)。
   现在程序会在点之前先确认这一点,并直接提示「XX 是以管理员身份运行的」,
   而不是写一句「已点击」骗人。两种解法任选:
     · 退出助手,右键 ZCodeAssistant.exe →「以管理员身份运行」;
     · 或让那个客户端不要以管理员身份运行(看快捷方式的兼容性/高级选项)。
   「签到目标」页的「校验坐标」也会提前把这层标红,不用等试运行。

问:banner 一闪就跳走,来不及点?
答:把该步的「点后等待」填 0,录制的顺序紧接着排,程序会连着点;
   也可以先手动停在有 banner 的界面,用「试跑」单独验证这一步。

问:领完之后弹窗一直挂着,第二天点开发现没领上?
答:给那个目标录一个「领取后补关」点(见第三节第 3 步)。补关点只在领取成功
   之后才点,日志「收尾」阶段会写明补点位置,留档图是 attempt-N-postM.png,
   回放能直接看出浮窗有没有被真的关掉。

问:用了一阵子 ALT 键像被按住了一样(菜单自己激活、点击变成 Alt+点击)?
答:那是抢前台时借用的 ALT 解锁键留下的按键残留。现在成对按键用一批事件发完
   (不会再一半落在旧窗口、一半落在新窗口),每场点完还会自查并补发抬起,
   日志里会写「修饰键残留已抬起:ALT」。若仍然出现,多半是别的程序按了没抬,
   重启助手会清一次。

问:面板打不开?
答:先确认程序还在运行(看任务栏);端口默认 8760,被占用会自动顺延,
   实际地址以日志(或启动时的提示)为准。

问:不想要动画?
答:面板地址后加 ?motion=0,例如 http://127.0.0.1:8760/?motion=0
   想换浅色主题加 ?theme=light


八、合规提醒
------------------------------------------------
仅用于自动化本人账号、本机的福利领取,单场点击次数极少(≤5 次 + 校验)。
请遵守 ZCode 服务条款;若官方推出「一键领取」入口或条款禁止此类自动化,
请停用本工具。
